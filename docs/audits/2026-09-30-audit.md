## Plan only — GitHub Pages mirror

**Recommendation: retire the mirror and redirect it to www.simonlaborde.com.**

Reasons:
- **It can't do much:** it can't send security headers (finding 3), has no chat, and duplicates content (the canonical tag mitigates SEO but not confusion).
- **It doubles the work:** every change has to pass two builds.
- **It's the main obstacle to i18n and stricter security:** no middleware or proxy, trailing-slash routing quirks, and the static-export constraint pushes every design toward the lowest common denominator.

**How:** GitHub Pages can't send a server-side 301. Replace the Pages artifact with a tiny static `index.html` and `404.html`: `<link rel="canonical">`, `<meta http-equiv="refresh" content="0; url=https://www.simonlaborde.com/">`, and a script that does `location.replace` while preserving path and hash. Google treats an instant meta refresh as a redirect. Old shared links keep working. Then drop `build:static` and the `STATIC_EXPORT` branch.

**Effort:** about 1 h. **Keep the mirror only if** some application already links to `simonrl13.github.io` and you'd rather it showed the full site. Even then the redirect page covers that.
